# Versioning and Stability

## Stable tool IDs

Tool IDs are canonical and stable. They are derived from:

```text
hash(method + normalized_path)
```

Example:

```text
GET:/api/orders/{id} -> tool_9f3a2c
```

## Tool names

Names are human-readable and may be generated by an LLM, but they must not change silently.

Rules:

- If a tool exists from a prior generation, preserve its name.
- If a tool was approved, lock its name until explicit user rename.
- If a tool was never approved, still preserve name by default to avoid breaking scripts.
- New LLM suggestions can be surfaced as rename suggestions.

Command:

```bash
tapestry rename acme.tool_9f3a2c listOrders
```

## Hash function changes

Changing the hash function or normalized path algorithm is a breaking change.

If this happens:

- mark affected tools as `needs_review`
- preserve old-to-new mappings when possible
- do not silently preserve approvals if identity is uncertain

## ToolSpec migrations

Commands:

```bash
tapestry validate acme
tapestry migrate acme
```

Migration guarantees:

- preserve tool IDs when possible
- preserve approvals only when identity is certain
- mark breaking or ambiguous changes as `needs_review`
